# Load-sensitive tests: their subject is throughput or real-time latency (frames streamed or interleaved at a pace, a
# time measured), so they can fail while other processes hold every CPU. The runners keep them out of their parallel
# workers and run them afterwards, one after another (a serial tail), and run a failed one once more: run_backend.py
# (python), tools/unittest_jobs.py (gui), core/tests/run_shards.py (core, the names from tools/test.py) and
# tools/test.py (dotnet, after every suite has ended). With one worker they run in their usual place, without a retry.
# A test whose subject is not the timing belongs on a stepped or virtual clock instead, not here.
# Format: the suite, a space, the test id, two spaces, the reason. Suites: core (an ec_tests name), python
# (module.Class.test), gui (gui.test_gui.Class.test), dotnet (the fully qualified name).
