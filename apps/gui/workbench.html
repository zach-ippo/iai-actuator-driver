    Start here

    An unofficial test tool for IAI ELECYLINDER and CON-family units.

    No hardware

    Simulated axes run the same driver code and never open a serial port.

    Two sliders on two ports: enough for the Group and Coordinated tabs.

    With a unit

    Close IA-OS first: only one program can use a port. Tick the port marked IAI and press Connect selected ports; the baud rate is detected. Start slow and short, and keep a hand on the emergency stop. Back up a unit (Functions > Back up this unit) before writing parameters or stored positions.

    Demo mode: serial ports are not listed. Start iai-gui without --sim-only to use a unit.

    Things to try

    1. Axis tab: Servo ON, Home, then a short slow move.
    2. During a move press Space or Esc: STOP ALL.
    3. Stored positions: run a row. Unit info & alarms: alarm history and Self-test.
    4. Group tab: move two axes together.
    5. Coordinated tab (experimental): Plan a small circle, check the plot, then Run.
    6. Test report: Copy, then paste it into a GitHub issue with what you did.

    What to report: the test report, the steps, what you expected and what happened, in an issue at github.com/zach-ippo/iai-actuator-driver. More in Getting started (section 4, Try the GUI without hardware).

    Known limits
    • Unofficial, not an IAI product.
    • STOP is a Modbus decelerate-stop, not a safety function.
    • A unit has no communication watchdog: a move in progress completes if the PC or cable fails.
    • Coordinated motion is experimental: one real axis with a simulated second VERIFIED, two real axes together UNVERIFIED.
    • Several axes on one port: UNVERIFIED.
    • The GUI listens on 127.0.0.1 only.

    Stored positions

    Every row the unit uses. Run moves to a row at its stored speed (optionally at a % of it). Write changes the row in the unit's non-volatile memory (verified by read-back; back up the unit first). Ranges come from the unit (stroke, MAXV, MAXA / MAXD, MXPP).

    Parameters

    The unit's named parameters with their units and ranges. A write is verified by read-back, saved to non-volatile memory and applies after a software reset or power cycle. Parameters marked dangerous (home direction / offset, encoder / motor type, lead / stroke, gains, axis number, baud) can make the axis move unexpectedly when set wrong: check the value against the unit's manual.

    Group moves need two or more axes

    Connect two units, or add two simulated axes (two sliders on two ports).

    All axes

    Each axis keeps its own units and ranges.

    Move together: every target is checked against its own unit's ranges and readiness before any axis starts (Cell.move_all); one bad value refuses the whole move, nothing is sent. A start that fails stops the axes already started.

    Test report

    Run the Self-test on each unit first (Unit info & alarms) for a fuller report. Paste the text into a GitHub issue with the steps, what you expected and what happened.

    The report names this PC's operating system, Python and browser, the ports and the units (model, firmware, serial number, state), the last errors and the event log. It never holds the access key. Read it before you send it: a GitHub issue is public.
